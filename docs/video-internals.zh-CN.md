# 工程视频后端约束

`reaper.video` 通过 Native Frame Streams 提供当前工程的最终合成画面。API、示例和主机兼容范围见[工程视频预览](video-preview.zh-CN.md)。

## 帧处理

后端读取当前工程对应的合成帧，并校验视频源、帧位置和缓存状态。有效帧转换为固定尺寸的 RGBA8 数据，保持源宽高比并填充不透明黑边。

连续播放时，先读取尚未采集的官方已选帧，再推进视频。此帧最多允许落后当前查询位置一帧，并仍须通过工程源、缓存帧及监视处理校验。

播放期间，选中帧的查询索引、源与监视处理哈希及时间戳均未变化时，跳过转换和像素复制。停止播放时不使用此去重规则，工程编辑、定位和播放状态变化会使帧标识失效。

宿主帧引用仅在读取期间持有，像素复制完成后释放。网页消费者接收独立像素数据，不持有宿主帧指针。工程时间用于帧时间戳，素材局部时间不直接作为工程位置。

源失效或渲染占用时，运行时清除有效源状态并发布黑色清屏。短暂等待解码时，从首次读取到等待解码状态起，保留最近有效帧最多 100 ms，持续等待超过此时限才清屏。工程编辑、定位和播放状态变化立即清除旧帧。清屏不计入有效采集帧数。后续有效帧恢复后，状态回到 `ready`。

## 调度与生命周期

独立视频调度器唤醒 REAPER 主线程，不依赖扩展定时器频率。工程帧率不超过 75 FPS，且以正常或更慢速度播放时，auto 直接跟随宿主的新帧。固定更新率、加速播放和更高工程帧率仍按目标速率限流。视频读取、转换、缩放和发布在该线程执行。工程视频使用三个采集槽位并按顺序读取，每个消费者允许两个帧等待确认、两个帧等待发送，队列满时丢弃最旧帧。多个消费者共享采集资源，普通 Native Stream 的缓冲策略不变。

Windows 传输线程仅在工程视频流活动期间使用高精度等待，减少轮询与 ACK 延迟，不可用时回退到普通等待。不修改系统定时器分辨率，保留现有包头长度与 ACK 协议。

播放期间选中帧未变化，或帧尚未就绪时，下一次调度唤醒即重试，不消耗额外的目标更新间隔。成功采集后再推进采集期限。

默认更新率为 `auto`，跟随工程帧率并保留小数精度，目标范围为 1–75 FPS。显式数字参数使用固定更新率。目标更新率与平均采集 FPS 分别报告，静态画面与低帧率素材仍可能产生视觉内容相同的采集帧，采集次数不等于不同画面或实际显示帧数。

Demo 在持续的浏览器刷新循环中顺序绘制，队列最多保留六个包，溢出丢弃最旧包。启动等待第二个包或约 16 ms，显式视频失效、时间戳跳变、关闭和错误清除待绘制内容。RWS v1 的保留字节 5 使用位 0 标识视频失效，SDK 暴露可选的 `discontinuity` 字段，包头和像素布局不变。此缓存增加有限排队延迟，也不能突破浏览器或屏幕刷新率限制。

最后一个消费者断开后停止采集。页面关闭、隐藏、重载、工程切换及扩展卸载会释放对应资源。工程切换关闭旧流，消费者需为当前工程重新打开。

## 兼容性与限制

- 不检查 REAPER 版本号，不维护支持版本列表。启动前检查平台/架构实现、视频模块和必要宿主接口是否存在，并校验规范化模块指纹。
- 启动条件不满足时返回 `VIDEO_HOST_UNSUPPORTED`，其他扩展功能仍可使用。
- 指纹排除指定构建元数据字段，保留代码、数据和布局校验。模块指纹必须与固定内部地址对应。指纹不匹配或文件无法读取时拒绝调用并返回 `VIDEO_HOST_UNSUPPORTED`。模块校验不替代实机兼容性验证。
- Linux 按模块指纹选择 7.82、7.84 或 7.85 对应的地址映射，不跨布局复用地址。
- RGBA 和 YV12 输入路径已验证。YUY2 尚未单独进行素材验收。
- 宿主负责原生帧格式转换，网页呈现可能受缩放、显示色彩管理和 GPU 处理影响。
- 实际更新率受宿主调度、工程负载、解码和网页绘制性能影响。显示帧率还受屏幕刷新率限制。
