# 工程视频后端约束

`reaper.video` 通过 Native Frame Streams 或 Windows、macOS 原生呈现表面提供当前工程的最终合成画面。API、示例和主机兼容范围见[工程视频预览](video-preview.zh-CN.md)。

## 帧处理

后端读取当前工程对应的合成帧，并校验视频源、帧位置和缓存状态。默认路径将有效帧转换为 RGBA8，按所选分辨率与宽高比策略输出。Windows x64 对已验证的 SSE I420 源帧在缩放输出 RGBA8 时按需转换源行并结合 SSE2 双线性插值，省去整帧中间转换。Windows x64、macOS ARM64 和 Linux x86_64 可选 I420 路径直接复制已验证的原生三平面，保持原始尺寸，不增加色度采样。

连续播放时，先读取尚未采集的官方已选帧，再推进视频。此帧最多允许落后当前查询位置一帧，使用对应帧索引重新计算视频源标识，并仍须通过工程源、缓存帧及监视处理校验。

播放期间，选中帧的查询索引、源与监视处理哈希及时间戳均未变化时，跳过转换和像素复制。停止播放时不使用此去重规则，工程编辑、定位和播放状态变化会使帧标识失效。

宿主帧引用仅在读取期间持有，像素复制完成后释放。网页消费者接收独立像素数据，不持有宿主帧指针。工程时间用于帧时间戳，素材局部时间不直接作为工程位置。

源失效或渲染占用时，运行时清除有效源状态并发布黑色清屏。动态预览在等待解码期间保留上一有效画面最多 500 ms，定位时从最新请求重新计时。自定义预览保留即时失效行为，普通解码等待在播放时最多保留 500 ms，停止时为 100 ms。清屏不计入有效采集帧数。后续有效帧恢复后，状态回到 `ready`。

## 调度与生命周期

独立视频调度器唤醒 REAPER 主线程，不依赖扩展定时器频率。工程帧率不超过 75 FPS，且以正常或更慢速度播放时，auto 直接跟随宿主的新帧。固定更新率、加速播放和更高工程帧率仍按目标速率限流。视频读取、转换、缩放和发布在该线程执行。工程视频使用三个采集槽位并按顺序读取，原生内存消费者允许两个帧等待确认，原始套接字允许三个，两条路径均允许两个帧等待发送，队列满时丢弃最旧帧。多个消费者共享采集资源，普通 Native Stream 的缓冲策略不变。

Windows 传输线程仅在工程视频流活动期间使用高精度等待，减少轮询与 ACK 延迟，不可用时回退到普通等待。不修改系统定时器分辨率，保留现有 ACK 协议。

播放期间选中帧未变化，或帧尚未就绪时，下一次调度唤醒即重试，不消耗额外的目标更新间隔。成功采集后再推进采集期限。

默认更新率为 `auto`，跟随工程帧率并保留小数精度，目标范围为 1–75 FPS。显式数字参数使用固定更新率。目标更新率与平均采集 FPS 分别报告，静态画面与低帧率素材仍可能产生视觉内容相同的采集帧，采集次数不等于不同画面或实际显示帧数。

Demo 的网页绘制路径在持续的浏览器刷新循环中顺序绘制，队列最多保留六个包且不超过 128 MiB，溢出丢弃最旧包。启动等待第二个包或约 16 ms，显式视频失效、时间戳跳变、关闭和错误清除待绘制内容。RWS v1 与动态分辨率的 v3 包头均使用字节 5 的位 0 标识视频失效，SDK 暴露可选的 `discontinuity` 字段。宿主重复位置后正常追赶时钟不会被误判为跳转。此缓存增加有限排队延迟，也不能突破浏览器或屏幕刷新率限制。

最后一个消费者断开后停止采集。页面关闭、隐藏、重载、工程切换及扩展卸载会释放对应资源。工程切换关闭旧流，消费者需为当前工程重新打开。

## Windows 与 macOS 共享原生呈现

`openSurface()` 在 Windows 使用原生 D3D11/DirectComposition 层，在 macOS 使用 Metal 层，HTML 控件与布局位于其上方。相同采集配置只上传和转换一次帧，各窗口共享 RGB 纹理，再按各自显示区域采样。窗口缩放不改变采集尺寸，也不引入中间降分辨率。Demo 的原生适配模式使用源分辨率采集并独立更新布局，自定义模式仍实际改变采集尺寸。

表面不向 JavaScript 提供像素，`readablePixels` 为 `false`，也不提供 `data`、`latest` 或 `read`。Canvas 与网页快照不包含原生层。需要网页像素访问时继续使用 `openStream()`。每个窗口最多一个表面，重复请求返回 `VIDEO_SURFACE_IN_USE`。原生层与像素流复用已有视频配置及生命周期，保留网页像素流与 Linux 绘制路径。共享处理减少重复工作，不保证固定窗口数量下的呈现帧率。

原生源使用三个有界槽位，传输线程同步复制一次借用帧，上传、I420 转换和呈现在后台执行。尺寸随帧传递，仅在槽位不再被 GPU 使用后调整其纹理，保留设备及显示资源。宽高比按当前帧计算，源尺寸变化不会重建未改变视口的 Windows 交换链或 Metal layer。原生 I420 接受有效偶数尺寸，按源行步长去除平面填充后上传。Windows 使用三平面纹理在 GPU 中缩放并转换 YUV，macOS 使用已验证的 NEON 整数公式进行 GPU 转换，RGBA8 直接上传。CPU 转换及像素流保留原有尺寸限制。保留当前帧用于暂停、布局变化及新窗口重绘。Windows 各窗口的 swapchain 按实际视口分配，共享源纹理不按窗口重复转换。窗口持有独立的 DirectComposition target，表面更换只替换自身 visual，旧表面的异步清理不移除新表面。

Windows 的 `presentedFrames` 仅累计 DXGI 统计中实际观察到的新源帧，不把成功提交数当作显示数。统计不可用时，呈现计数与 FPS 为 `null`，内容就绪状态独立保留。单个视口绘制失败关闭该表面，设备移除使共享源失败。Demo 遇到原生呈现不可用或呈现器失败时回退网页绘制，SDK 保留表面与像素流的接口区别。

## 兼容性与限制

- 不检查 REAPER 版本号，不维护支持版本列表。启动前检查平台/架构实现、视频模块和必要宿主接口是否存在，并校验规范化模块指纹。
- 启动条件不满足时返回 `VIDEO_HOST_UNSUPPORTED`，其他扩展功能仍可使用。
- 指纹排除指定构建元数据字段，保留代码、数据和布局校验。模块指纹必须与固定内部地址对应。指纹不匹配或文件无法读取时拒绝调用并返回 `VIDEO_HOST_UNSUPPORTED`。模块校验不替代实机兼容性验证。
- Linux 按模块指纹选择 7.82、7.84 或 7.85 对应的地址映射，不跨布局复用地址。
- RGBA 和 YV12 输入路径已验证。YUY2 尚未单独进行素材验收。
- RGBA 路径由宿主转换原生格式。I420 路径限定指纹与转换器已验证的 Windows x64、macOS ARM64、Linux x86_64 BT.709 转换，GPU 匹配其定点截断和舍入。网页呈现仍可能受缩放、显示色彩管理和 GPU 处理影响。
- 实际更新率受宿主调度、工程负载、解码和网页绘制性能影响。显示帧率还受屏幕刷新率限制。

## 输出分辨率

`getSourceInfo()` 查询最终有效帧，不从单个素材或工程帧率推断尺寸。异步解码未就绪时返回零尺寸，并最多保留五秒探测状态。`fit` 按物理显示区域解析尺寸且不放大，`source` 使用源尺寸，旧宽高调用继续使用 `custom`。适配与原始模式在当前流内处理最终尺寸变化，适配边界保持为最初请求值。自定义模式保留固定尺寸。动态流标识为 `dynamicResolution: true`、`layoutVersion: 3`，每帧携带宽、高和步长，连接描述仅为初始快照。尺寸超限时清屏并保留连接，恢复有效尺寸后继续采集。

视频专用单帧预算为 40 MiB，单边不超过 8192。普通 Native Stream 的 16 MiB 单帧上限不变，动态流的三个采集槽位分别按 40 MiB 计入共享的 256 MiB 预算，实际帧长度独立记录。视频输出池按实际分配容量限制为 240 MiB，在途套接字帧须为下一帧发布预留空间。压力下回收可替换的待发送快照，不覆盖仍被引用的像素。配置切换释放未被引用的旧容量。等尺寸保持 RGB 值，缩放使用双线性滤波。适配模式只计算一次比例，避免整数取整后再次缩放产生多余黑边。

Windows 使用只读共享槽位，Linux 通过 WebKit 视频模块读取原生槽位，macOS 的像素流使用窗口独占的本地视频资源。动态流的每个原生内存消费者预留两个 40 MiB 槽位，地址固定，仅复制实际帧长度。普通 SDK 流完成像素复制后才确认槽位复用。Windows 专用视频工作线程直接持有映射，上传或丢弃后 ACK，关闭时归还映射。macOS 响应持有槽位内存引用，省去中间快照复制，关闭后旧地址失效。Demo 的网页绘制路径对已验证 I420 保留原始纹理，在实际显示像素上合并整数 RGB 转换与双线性采样，原始像素模式保持 1:1。其他源保留各平台的 RGBA 呈现路径。
