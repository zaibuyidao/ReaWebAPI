# 工程视频后端约束

`reaper.video` 通过 Native Frame Streams 提供当前工程的最终合成画面。API、示例和主机兼容范围见[工程视频预览](video-preview.zh-CN.md)。

## 帧处理

后端读取当前工程对应的合成帧，并校验视频源、帧位置和缓存状态。有效帧转换为固定尺寸的 RGBA8 数据，保持源宽高比并填充不透明黑边。

宿主帧引用仅在读取期间持有，像素复制完成后释放。网页消费者接收独立像素数据，不持有宿主帧指针。工程时间用于帧时间戳，素材局部时间不直接作为工程位置。

源失效、等待解码或渲染占用时，运行时清除有效源状态并发布黑色清屏。清屏不计入有效采集帧数。后续有效帧恢复后，状态回到 `ready`。

## 调度与生命周期

视频读取、转换、缩放和发布在 REAPER 主线程执行。帧传输复用现有有界二进制流，多个消费者共享采集资源。

默认更新率为 `auto`，跟随工程帧率并保留小数精度，目标范围为 1–60 FPS。显式数字参数使用固定更新率。目标更新率与实际输出 FPS 分别报告。

最后一个消费者断开后停止采集。页面关闭、隐藏、重载、工程切换及扩展卸载会释放对应资源。工程切换关闭旧流，消费者需为当前工程重新打开。

## 兼容性与限制

- 不检查 REAPER 版本号，不维护支持版本列表。启动前检查平台/架构实现、视频模块和必要宿主接口是否存在，并校验视频模块 SHA-256。
- 启动条件不满足时返回 `VIDEO_HOST_UNSUPPORTED`，其他扩展功能仍可使用。
- 当前仍使用固定内部地址，模块指纹必须与这些地址对应；指纹不匹配或文件无法读取时拒绝调用并返回 `VIDEO_HOST_UNSUPPORTED`。模块校验不替代实机兼容性验证。
- RGBA 和 YV12 输入路径已验证。YUY2 尚未单独进行素材验收。
- 宿主负责原生帧格式转换，网页呈现可能受缩放、显示色彩管理和 GPU 处理影响。
- 实际更新率受宿主调度、工程负载、解码和网页绘制性能影响。
